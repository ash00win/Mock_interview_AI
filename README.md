# Mock Interview AI

A Flask web app that runs an AI-generated mock interview and proctors it through
the webcam. Candidates sign in with their face, answer role-specific questions
generated by Google Gemini, speak or type their answers, and finish with a score
plus a reading of the facial expression they held during the session.

> **Platform note:** this runs against the machine's local webcam and uses
> `winsound` for proctoring alerts, so it is Windows-only and meant to be run
> locally rather than deployed.

---

## Features

**Face-based sign-in.** A user uploads three photos at registration. Those are
encoded with `face_recognition` (dlib, HOG detector) and serialized to
`faces.pickles`. Before an interview starts, the webcam takes a frame, encodes
the detected face, and matches it against the known encodings at a 0.4 tolerance
— so the person taking the assessment is the person who registered.

**AI-generated question sets.** Picking a role calls Gemini
(`gemini-1.5-flash`) ten times for distinct, graduate-level theory questions,
then once more per question for a one-line reference answer. Both are stored in
MySQL, so a session is reproducible and gradeable rather than thrown away.

**Automatic answer scoring.** Each submitted answer is compared against the
reference answer with `difflib.SequenceMatcher`; a similarity ratio above 0.8
scores the question correct. The final page reports the percentage.

**Live emotion proctoring.** While the interview is running, a background thread
reads the webcam, detects faces with an OpenCV Haar cascade, and classifies the
48×48 grayscale face crop with a Keras CNN across seven emotions
(angry, disgust, fear, happy, neutral, sad, surprise). The latest label and
confidence are surfaced on the results page. If no face is detected for 30
consecutive frames, the app beeps — the candidate has looked away.

**One attempt per role per day.** Question generation is keyed on
`(user, role, date)`, so a candidate can't farm the same role repeatedly.

**Admin console.** Manage interview roles, view registered users, read and reply
to user complaints, and publish notifications.

## How a session flows

```
register (3 photos) ──► face encodings written to faces.pickles
                                    │
login ──► role selection ──► face verification ──► questions generated (Gemini)
                                                          │
                              ┌───────────────────────────┴────────────┐
                              │                                        │
                    question loop:                        emotion detection thread:
                    answer ──► similarity score           webcam ──► Haar cascade ──►
                    ──► next question                     Keras CNN ──► label + confidence
                              │                                        │
                              └───────────────► results page ◄─────────┘
                                          (score % + emotion + confidence)
```

## Tech stack

| Layer | Technology |
|---|---|
| Web framework | Flask (blueprints: `public`, `user`, `admin`) |
| Database | MySQL (`mysql-connector-python`, `pymysql`) |
| Question generation | Google Gemini API (`google-generativeai`, `gemini-1.5-flash`) |
| Face recognition | `face_recognition` (dlib), OpenCV |
| Emotion detection | TensorFlow / Keras CNN + OpenCV Haar cascade |
| Answer matching | `difflib.SequenceMatcher` |
| Frontend | Jinja2 templates, HTML/CSS/JS |

## Project structure

| File | Responsibility |
|---|---|
| `main.py` | App entry point; registers the three blueprints |
| `public.py` | Home, login, registration (including the three training photos) |
| `user.py` | Profile, role selection, interview loop, scoring, emotion thread |
| `admin.py` | Roles, users, complaints and replies, notifications |
| `database.py` | Thin `select` / `insert` / `update` / `delete` MySQL helpers |
| `face_model.py` | Builds face encodings from the training images |
| `face_recognize.py` | Webcam capture and face matching at interview start |
| `voice.py` | Gemini client, question fetching, answer similarity |
| `model_manager.py` | Model loading helper |
| `model/` | Haar cascade and model architecture JSON |

## Setup

**Requirements:** Python 3.10+, MySQL, a working webcam, and a
[Google Gemini API key](https://aistudio.google.com/app/apikey).

`face_recognition` depends on dlib, which needs CMake and a C++ build toolchain
installed before `pip install` will succeed.

```bash
git clone https://github.com/ash00win/Mock_interview_AI.git
cd Mock_interview_AI

python -m venv venv
venv\Scripts\activate

pip install -r requirement.txt

copy .env.example .env       # then fill in GOOGLE_API_KEY
```

Create a MySQL database named `ai_interview` and point `database.py` at your
own credentials, then:

```bash
python main.py               # http://127.0.0.1:5000
```

## Known limitations

Written up honestly, since this was an academic project built to a deadline:

- **SQL is assembled with string interpolation** in `admin.py`, `public.py`, and
  parts of `user.py`, which leaves it open to injection. `voice.py` and
  `create_and_store_questions` use parameterised queries; the rest should be
  migrated to match.
- **Credentials are hardcoded** in `database.py` and `voice.py`. Only the Gemini
  key was moved to `.env`; the database login should follow.
- **Passwords are stored and compared in plaintext** rather than hashed.
- **Answer scoring is string similarity, not semantics** — a correct answer
  worded differently from the reference scores zero.
- Emotion detection opens an OpenCV window on the server machine, which is why
  this only makes sense as a locally-run application.
